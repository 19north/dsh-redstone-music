### ③ ★ 音高公式的隐含约定 —— 本轮"全是错音"的根因

生成器算 note 值的公式原本是：

```
note = midi − win[0]        ← 隐含约定：采样必须录在 "win[0] + 12" 这个音高！
```

因为 `playPitch = 2^((note−12)/12)` ✓，要让音符盒正好奏出 midi 那个音，就必须 `note − 12 = midi − 采样录音音高` ✓。

**我犯的错**：为了减小移调量（让音色更自然 ✓），把三条钢琴采样改录到了**音域中心**（64/78/90 ✓）
而不是"窗口低端+12"（68/84/96 ✗）→ **三条钢琴轨分别低了 4 / 6 / 6 个半音** ✗✗ → 用户听到"全是错音" ✓

**修法（已改）**：给轨表加**显式 `sample` 字段**（采样录音音高 ✓），公式改为

```
note = midi − sample + 12      // sample 缺省时回退 win[0]+12（= 老行为 ✓）
```

→ 采样可以录在**任意**音高 ✓（音域中心 → 移调最小 ✓ 音色最好 ✓）且音高**绝对准确** ✓
→ 本轮实测：钢琴三条轨移调 −4..+7 / −6..+5 / −6..+2 ✓，**抽查 11/11 note 值正确** ✓✓（`verify-virus-pitch.mjs`）

**教训**：**采样录音音高必须显式记录**，不能靠"窗口低端+12"这种隐式约定 ✗ —— 以后再加轨/换采样，先核对这条 ✓

### ④ ★ 建造任务运行期间，绝对不要用别的脚本碰 RCON

2026-10-01 我一边跑建造 ✓ 一边发起 `fix-virus-taps` / `virus-fx` / 抽查 ✗（以为锁机制会互斥 ✓）
→ `rcon-lib` 的锁是**建议性**的 ✓，新进程发现持有者 pid 已不存在（其实是我中断的进程 ✗）就**接管**了 ✗
→ 建造任务失去连接 → 失败 → **从头重启**（进度从 1575 退回 257 ✗）
→ 而重启时会先跑 `--clean` ✗ → **整条带子被清空** ✗✗，白干 25 分钟 ✓

**规则**：
1. 建造/长任务运行期间，**只用"读日志文件"看进度** ✓✓（`Get-Content latest.log -Tail N` 取 `Changed the block at (x)` ✓）
2. 所有需要 RCON 的收尾脚本（补丁/铺灯/验证）**必须等建造结束再串行跑** ✓
3. **不要中途 abort 工具调用** ✗ —— abort 掉的进程会留下"锁持有者已不存在"的假象，诱使后续进程抢锁 ✓

## ★ 必须打的补丁：抽头中继器（`fix-virus-taps.mjs`，已写好）

**这是今晚踩到的真 bug** ✓ —— 值得记住：

```
每条轨的抽头 = 总线(x=248) ──红石粉──→ 该轨首级中继器(x = xStart = 250 + 2*delay)
红石粉每格衰减 1，而总线上的"刷新中继器"每 ~10 格一个 → 段末强度只剩 6
  delay=3 的轨：抽头 8 格粉 → 6−7 = −1 → 信号归零 ✗ 首级永远不触发（定音鼓就是这么死的）
  delay=2 的轨：抽头 6 格粉 → 6−5 =  1 → 勉强能通 ✓（这就是为什么只有长延迟的轨会死）
```

**修法**：把每条轨抽头的**最后一格红石粉换成中继器** ✓（`facing=west` ✓，延迟 1 ✓）
→ 信号在末端被刷新 ✓✓，而且**每条轨都 +1 刻 ⇒ 整体平移，轨间关系不变** ✓✓（听感上就是整曲晚 47ms，无人察觉）

### ⚠ 两个必须记住的方向性坑

1. **中继器的 `facing=X` 表示"输入来自 X 边"** ✓（不是"朝 X 输出" ✗）
   - 波前是向**东**推进的 ✓ → 所以所有中继器都是 `facing=west` ✓（输入来自西边 ✓）
   - 我今晚插反过一次（写成 east ✗）→ 它的输入指向下游，永远收不到信号 ✗
2. **验证必须用"永久的执行记录"** ✓，不能掐时间读方块状态 ✗
   - 按钮脉冲只持续约 0.5 秒 ✓ → 等 2 秒再读 `powered` 必然是 false ✗（我因此误判过两次 ✗）
   - 正确做法：读粒子指令方块的 `data get block <x> <y> <z> LastExecution` ✓（它永久记录最后一次执行的刻 ✓）
   - 现成脚本：`verify-timpani.mjs` / `measure-lane-phase.mjs` ✓
