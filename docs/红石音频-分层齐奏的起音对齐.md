# 红石音频：分层齐奏的"起音对齐"（2026-10-01 实战）

> 《Beethoven Virus》完全按原曲版做完后，用户反馈：
> **"感觉音不同步，同一时间的两个钢琴感觉有时差所以很乱"**
> 排查与修复过程记录如下 —— 这是**音频层**的坑，和方块/红石的坑完全不同。

## 二、真凶：采样的起音速度差异

原曲主旋律是 **钢琴（轨2）+ 弦乐震音（轨6）齐奏**（两条轨音符完全相同 ✓）
→ 同一个音由**两层**同时奏出 ✓

| 层 | 起音到峰值 | 听感 |
|---|---|---|
| 钢琴 GM0 | **13 ~ 36 ms** ✓ | 一敲就响 |
| 弦乐震音 GM44 (Tremolo Strings) | **224 ~ 293 ms** ✗✗ | 慢慢涨上来 |

→ 钢琴先响 ✓、弦乐 200 毫秒后才涨到最大 ✗
→ 耳朵听到的是 **"晚了半拍的第二个钢琴"** ✗ → **"很乱"** ✓✓

（原曲里也有这两层 ✓，但 MuseScore 播放时弦乐的**力度曲线**和采样不同 ✓；
而且我原来给弦乐 5 条轨擅自做了 30 ms 的"逐样本不同裁剪" ✗，
导致**弦乐各轨之间**还有 **18 ms** 的差异 ✗✗）

---

## 三、修法

### ① 慢起音的音色换掉 ✗ → 换快起音的同类音色 ✓

```
弦乐 GM44 (Tremolo Strings，峰值 224~293ms ✗)
  → GM48 (String Ensemble 1，峰值 8ms 内 ✓)
```
代价：丢了 tremolo 的震音质感 ✗ 但**时间对齐**远比这个重要 ✓

### ② 所有采样统一"起音裁切" ✓

```js
// 统一规则：裁到"达到峰值 60%"处，上限 120ms，然后套 2ms 淡入
let cut = 0;
for (let i = 0; i < total; i++) if (Math.abs(L[i]) >= 0.6 * peak) { cut = i; break; }
cut = Math.min(cut, Math.floor(SR * 0.12));
```

**绝对不能**对每个采样做不同规则的裁剪 ✗ —— 那等于给每条轨加**不同的延迟** ✗✗
（我第一版就是"裁到峰值的 90%、上限 30 ms" ✗ → 钢琴被裁 5~8 ms ✓、弦乐被裁 30 ms ✗ → 差 20+ ms ✗）

### ③ 渲完立刻测量并打印 ✓

每个采样的起音毫秒数都打出来 ✓ —— 差异 > 2 ms 就要重新查 ✓

**修完实测**：28 个采样起音 **0.25 ~ 1.45 ms** ✓✓
钢琴 4 轨之间 **0.36 ms** ✓、弦乐 5 轨之间 **0.91 ms** ✓、**钢琴↔弦乐跨层约 0.2 ms** ✓✓

## 四、通用结论（以后所有曲子都适用）

1. **分层齐奏（同一音符两件乐器）时，各层采样的起音必须接近** ✓
   否则听感就是"错拍" ✗，用户会说"有时差/很乱"，而**不是**"音不对" ✓
2. **打击乐（快起音）和长音（慢起音）绝不能齐奏同一音符** ✗
3. 判断"是不是起音问题"的最快实验：
   **把可疑的那一层单独静音/换成别的音色** ✓ 如果"错拍感"消失就是它 ✓
4. 渲染脚本务必**统一规则** ✓ 并在渲染后**测量输出** ✓（别凭感觉 ✓）
5. 相关脚本：
   - `measure-onsets.mjs` —— 测量所有采样的起音/峰值位置 ✓
   - `sound/fix-strings-attack.cjs` —— 换快起音音色 + 统一起音裁切 + 渲完即测 ✓
   - `diag-virus2-pitch.mjs` —— 排除"音高错误"用的世界数据诊断 ✓
